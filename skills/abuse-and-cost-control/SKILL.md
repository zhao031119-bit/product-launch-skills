# 防滥用和成本控制

AI 产品每次生成都要付钱给模型服务商：被刷一晚，可能比一个月的收入还多。下面这些在开发时就写进代码，上线前测过。

## 1. 免费额度
- 邮箱验证过才发（Google 登录的邮箱算已验证）；每个账号只发一次，发放记进点数流水（→ `payments-and-billing`）。
- 同一个邮箱的变体算同一个人：Gmail 忽略点和 `+` 后面的部分（`a.b+1@gmail.com` 就是 `ab@gmail.com`）。一次性邮箱不发免费额度。
- 同一个 IP 短时间内大量注册：限流，或者先不发免费额度。
- 免费额度够体验一次核心功能就行，别多给。

## 2. 注册、登录、结账
- 注册和登录加人机验证（例 Cloudflare Turnstile）；失败多次就限流。
- 结账：创建支付会话的接口按 IP 和账号限流。盗卡的人会拿你的结账页一张张试卡，拒付多了支付商会关你的账户；打开支付商自带的风控（例 Stripe Radar）。
- 限流放在服务端：先按 IP，登录后按账号；超了返回 429，告诉用户多久后再试。

## 3. AI 调用
- 每个用户每天的生成次数（或花费）有上限，免费用户更低。
- 同一个用户同时只跑有限个任务，其余排队。
- 输入有上限：文本长度、文件大小、视频时长。超了直接拒绝，不发给模型。
- 先扣额度再调用模型，失败了再退回（→ `ai-feature-prompts`）。先调用后扣费的话，并发请求能把余额刷成负数。

## 4. 总花费上限和告警
- 上线前在每个模型服务商的后台设好每月花费上限和用量提醒（→ `deploy-checklist`）。
- 自己的后台按天统计调用次数、花费、失败率；超过平时几倍就发告警（邮件或聊天群机器人）。
- 留一个开关：出事时能马上暂停免费额度或某个模型，不用重新部署。

## 5. 上线前自查
- [ ] 新注册一个账号：免费额度只到账一次；同一个 Gmail 加 `+1` 再注册，不会再给。
- [ ] 连续快速调用生成接口：会被限流，返回 429。
- [ ] 同时发几个生成请求：余额不会变成负数。
- [ ] 各个模型服务商的花费上限都设好了（记下数值或截图）。
- [ ] 暂停开关真的试过一次。
