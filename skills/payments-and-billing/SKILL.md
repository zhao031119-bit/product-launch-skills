# 收费与订阅

定价模式怎么选 → `product-strategy`。这里讲怎么实现。

## 1. 选支付商
| | Stripe 这类（你是卖方） | Paddle、Lemon Squeezy、Creem 这类 MoR（它是卖方） |
|---|---|---|
| 销售税、VAT | 责任在你（Stripe Tax 能帮着算税、登记、申报，责任不转移） | 它代收代缴 |
| 手续费 | 低一些 | 高一些 |
| 适合 | 公司所在国家支持、愿意自己管税 | 个人或小团队、卖给全球用户 |

- 先看支付商的禁售和限制清单：AI 换脸、名人肖像、成人内容这类产品常被拒，或者要额外审核。

## 2. 数据怎么存
- 价格、套餐、额度只从服务端目录取，不信前端传来的数字。
- 订单表：每笔支付一行，支付商的订单号加唯一索引，记金额、币种、状态。
- 点数：用流水表（购买、消耗、退还、过期各记一行），余额要能和流水对上；不要只存一个数字。
- 订阅：记套餐、状态（试用中、有效、扣款失败、已取消）、当前周期的结束时间。权益只看服务端这些字段。

## 3. webhook
- [ ] 先验签（或拿订单号向支付商回查），验过再核对商户号、金额、币种。不验签，这些字段都能伪造。
- [ ] 幂等：同一个事件、同一个订单只处理一次（事件 ID 去重，订单号唯一索引）。
- [ ] 回调地址在支付商后台填规范网址（https + 主域名 + 无末尾斜杠）。Stripe 等不跟随跳转，3xx 直接算投递失败（→ `seo-launch`）。
- [ ] 事件可能乱序、重复、迟到：以支付商那边的最新状态为准，拿不准就回查。
- [ ] 处理失败就返回非 2xx，让支付商重试；失败记下来，能手动补。

## 4. 订阅的几种情况
- 试用：要不要先绑卡；试用结束前发邮件提醒。
- 升级立刻生效、按比例补差价；降级到周期末生效。
- 取消：到周期末才停权益，期间照常能用。
- 扣款失败：支付商会自动重试；期间保留权益几天，发邮件让用户更新卡，最后才停。
- 用户能自己管理订阅：设置页链到支付商自带的客户管理页面（例 Stripe Customer Portal）。

## 5. 退款和拒付
- 生成失败、服务没交付：自动退额度（→ `ai-feature-prompts`）。
- 退款政策写清楚：多少天内、什么情况能退、已用额度怎么算（→ `compliance-and-copy`）。
- 退款和拒付（chargeback）也走 webhook：收回对应的额度或权益。
- 拒付率高了会被支付商关账户：盗卡、滥用先在产品里拦住。

## 6. 页面和审核
- 定价页和结账页：每档写清能做什么、按月还是一次性；写明安全托管结账、支持的付款方式、税在结账时计算。
- 价格处处一致：定价页、FAQ、结构化数据、llms.txt。
- 支付商审核看网站：产品介绍和真实功能一致、能看到价格、5 个法律页面、联系方式（→ `compliance-and-copy`）。

## 7. 上线前后
- [ ] 测试模式把每种情况走一遍：购买、续费、升级、降级、取消、扣款失败、退款。
- [ ] 切正式模式：正式的 API key 和 webhook 密钥都换上，webhook 地址指向生产。
- [ ] 上线后用真卡买一次最便宜的套餐，再退一次款，确认权益、流水和后台都对。
