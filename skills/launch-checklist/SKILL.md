# 产品上线总清单

怎么用：
- 开新项目时，先把 `references/project-rules.md` 里的规矩写进项目的 CLAUDE.md，再从头过一遍清单，把不做的项写上理由。
- 每次部署前，再过一遍「6 SEO」「9 部署」。
- 细节都在专项 skill 里，这里只放"别忘了"。例子换成你自己产品里对应的东西。

## 核对时怎么汇报
每一项给出状态和证据，例：

| 项 | 状态 | 证据 |
|---|---|---|
| sitemap 只放返回 200 的网址 | 通过 | `seo-check` 输出 All clear |
| 退款政策页 | 没过 | 首页页脚没有链接 |
| Google 应用已发布 | 没验证 | 要你在 Google Cloud 后台看 |

- 状态只有三种：通过、没过、没验证。没跑过检查、没看到证据的，一律写"没验证"，不写"应该没问题"。
- 证据写具体：命令和输出、网址和返回码、文件路径和行号、截图。
- 要用户自己操作的（后台设置、真实付款），最后单独列一张清单交给用户。

## 0. 定位与定价 → `product-strategy`
- [ ] 一句话说清产品：给谁用、输入什么、得到什么（例：一张照片 → 13 秒 9:16 MP4；一份合同 → 风险条款清单）。
- [ ] 需求从哪来：搜索词、热点、社区里反复出现的抱怨、竞品差评。热点产品记下趋势开始的日期。
- [ ] 去 ChatGPT 侦察：它推荐谁、怎么描述（→ `working-with-ai`）。
- [ ] 定关键词：用户真实的叫法（"<名词> generator / template / tool / app / alternative"）。
- [ ] 定价模式：订阅、点数包还是一次性买断；有没有免费额度或试用。
- [ ] 域名：含核心词、短，但别放别人的商标（ChatGPT、TikTok、Notion…）。

## 1. 搭建
- [ ] 首屏让人一眼看懂、马上能开始：工具类产品首屏就是工具；B2B 产品首屏讲清结果，配演示和注册按钮。手机上能用。
- [ ] 首页区块：示例或演示、3 步怎么用、适合谁、为什么选我们、对比表、价格、FAQ、结尾 CTA。
- [ ] 站名可以是品牌，但首页 `<title>` 以搜索词开头。
- [ ] 产品事实只写一处：套餐、价格、额度、免费额度、模型名、支持的语言、联系邮箱写进一个配置文件（例 `src/config/product.ts`）。定价页、FAQ、JSON-LD、llms.txt、结账、邮件都从它取；文案里的数字用占位符（例 `{price}`），不手写。
- [ ] 复用上一个项目的模板和组件，改名即可，别从零写。
- [ ] 页脚有联系邮箱：支付审核和用户反馈都要用。

## 2. 核心功能
- [ ] 新用户多快能拿到第一个结果：能不注册先试的，就让用户先试。
- [ ] 默认值就是大多数人想要的；选项只在确实有人用时才加。
- [ ] 额度、限流、权限都在服务端判断。
- [ ] 防滥用和成本上限：免费额度只发一次；注册和结账有人机验证和限流；AI 调用每个用户每天有上限；模型服务商设了花费上限（→ `abuse-and-cost-control`）。
- [ ] AI 功能：提示词在服务端拼；每个选项都跑过真实生成；失败自动退额度（→ `ai-feature-prompts`）。

## 3. 登录与账号 → `auth-and-accounts`
- [ ] 登录方式：To C 以 Google 为主，邮箱验证码或魔法链接兜底；开发者工具加 GitHub。
- [ ] Google 登录：回调地址、JS 来源、发布应用。
- [ ] 发信域名配好 SPF、DKIM、DMARC：验证码和魔法链接要能进收件箱。
- [ ] 用户能自己删账号；第一个管理员怎么设。

## 4. 收费 → `payments-and-billing`
- [ ] 支付商：Stripe 这类（你是商户，税自己管），还是 Paddle、Lemon Squeezy、Creem 这类代收代缴税的 MoR。先看它的禁售清单。
- [ ] 金额、套餐、额度只信服务端；webhook 先验签再改权益，并且幂等；回调地址填规范网址（3xx 会被当成投递失败）。
- [ ] 订阅：试用、升降级、取消、扣款失败怎么处理；用户能自己管理订阅。
- [ ] 上线后真买一次、退一次款。

## 5. 合规与文案 → `compliance-and-copy`
- [ ] 隐私、条款、Cookie、退款、可接受使用：5 个页面都要有。
- [ ] 隐私政策写明用户数据交给了哪些第三方（AI 服务商、支付、分析、邮件）；有欧盟访客就要有 Cookie 横幅，同意后才写分析 Cookie。
- [ ] 只写做得到的事："免费""无限""秒出"只在真的时候写；评价和案例要真实。
- [ ] 别人的素材（视频、图片、音频、文字）：能不用就不用，风险写下来；示例尽快换成自己产品做出来的。
- [ ] 用到别人的产品名时，写"非官方、与 X 无关"的声明。
- [ ] 上线前跑 `site-audit`：法律页面、联系邮箱、禁用词、支付回调地址（→ `compliance-and-copy`）。

## 6. SEO 与 GEO → `seo-launch`
- [ ] 每页只有 1 个指向自己的 canonical；title ≤ 60 字符，description ≤ 160。
- [ ] sitemap 里只放直接返回 200 的网址；robots.txt 写 Sitemap 行；有 llms.txt。
- [ ] 跳转只跳一次，用 301：http→https、www 和裸域选一个、去掉末尾斜杠。
- [ ] 该有的页面：定价页、对比页（X vs Y、X alternatives）、使用场景页、答案页（每个长尾问题一页）。
- [ ] 结构化数据只写页面上真有的内容；不指望出富结果。
- [ ] 上线后跑 `seo-check`，全绿再提交 GSC（网域资源）、Bing（从 GSC 导入）和 IndexNow。

## 7. 多语言 → `multilingual-site`
- [ ] 先翻带来流量的页面（通常是首页），再翻定价页、应用界面、邮件。
- [ ] 只按 URL 定语言，不按 cookie 或浏览器语言自动跳。
- [ ] hreflang 互相指向，加 x-default；每种语言有自己的 title 和 description。

## 8. 埋点 → `funnel-analytics`
- [ ] 先定"激活"：用户第一次拿到产品价值的那一步。
- [ ] 来访 → 注册 → 激活 → 看到价格 → 去付款 → 付款 → 续费或流失，每步一个事件。
- [ ] GA4 看所有访客；后台时间线看登录用户；付款以服务端订单为准，到账后由服务端给 GA4 发 `purchase`。

## 9. 部署上线 → `deploy-checklist`
- [ ] 等明确说"上线"才部署。
- [ ] 数据库迁移前留恢复点；迁移要兼容上一个版本的代码：回退只回滚代码，不回滚数据库。
- [ ] 密钥只进平台的 secret，不进代码、不发聊天。
- [ ] 冒烟：页面 200、登录回调、支付回调地址、关键接口、静态资源。
- [ ] 管理员：先正常登录一次，再提升权限。
- [ ] 填 AI 和支付密钥，跑一遍核心流程，完整买一次。

## 10. 上线后
- [ ] GA4 实时报告：事件有没有进来。错误监控：出错了你能先知道。
- [ ] GSC 覆盖率、Bing 收录；在 ChatGPT 里搜一次，看能不能找到自己。- [ ] 推广：目标用户在的社区、Product Hunt、Hacker News（Show HN）、目录和导航站（也是外链）（→ `product-strategy`）。
- [ ] 按数据删选项、改文案，每次只改一处。
- [ ] 换掉在聊天里出现过的密钥。

## 和 AI 协作 → `working-with-ai`
不可逆的操作用明确字眼授权："上线""提交代码""删除"。想停就直接说"停"。
