# 项目常驻规矩

开新项目时，把下面这段写进项目的 CLAUDE.md（`<…>` 换成项目里的实际内容）。skill 只在用到时才读，这几条不管做什么任务都要遵守。

```markdown
## 授权
- "上线" = 可以部署到生产；"提交代码" = 可以 commit / push；"删除 X" = 可以删 X。没说就不做，先问。
- 用户说"停"就停下，先汇报做到哪了。

## 密钥
- 密钥只通过管道或平台的 secret 命令传：不打印、不写进代码和提交、不贴进回复。
- 用户在聊天里发了密钥：用完提醒用户之后去服务商后台换一个。

## 做完要有证据
- 说"做好了"之前先验证：跑测试、跑检查脚本、看页面返回码。
- 汇报时每一项写"通过 / 没过 / 没验证"，附证据（命令和输出、网址和返回码、文件位置）。没验证的写"没验证"，不写"应该没问题"。

## 产品事实
- 套餐、价格、额度、免费额度、模型名、支持的语言、联系邮箱都在 `<产品事实文件，例 src/config/product.ts>`。
- 改价格只改这里。页面、FAQ、JSON-LD、llms.txt、结账、邮件都从它取，文案里不手写这些数字。
```
