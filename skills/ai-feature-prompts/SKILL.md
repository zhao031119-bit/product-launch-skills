# AI 生成功能的提示词

## 1. 先拆清楚"好结果"长什么样
- [ ] 找 3–5 个目标样本（爆款视频、写得好的文案、理想的图片），逐个拆：结构、长度、节奏、风格、必须保留的元素。
- [ ] 能量的就量出来，别凭印象：视频看帧差和音频波形，文案数段落和字数，图片看构图和比例。
- [ ] 写成一份规格：输入是什么、输出必须有什么、绝对不能有什么。

## 2. 提示词结构
1. 开头一句：格式（视频的比例和时长、文案的字数和语气、图片的尺寸和风格）。
2. 主体：用户给的输入（照片、文本、文件）是什么，哪些必须保留。
3. 结构或时间轴：分段写清每段做什么（视频按秒，长文按段落）。
4. 参考素材：每个参考写明角色。例：`@Image1` 是主角、`@Audio1` 是整条音轨、示例文本只学语气不抄内容。
5. 约束：不能出现什么（多余的文字、字幕、水印、别人开口），输出格式（JSON、Markdown）。

## 3. 安全和长度
- 提示词在服务端按 ID 拼出来；浏览器只传选项 ID 和用户自己的内容。
- 用户的文本放进提示词时，标明那是"用户内容"、限制长度，别让它改写你的指令。
- 不写名人、换脸、deepfake 一类词（→ `compliance-and-copy`）。
- 写单元测试：每个选项组合，提示词长度都在模型或接口的上限内（例：自家接口限 2000 字符）。快到上限时，加一句就要删一句。

## 4. 测试
- [ ] 每个选项至少一条真实生成；输入覆盖典型和极端情况（例：视频的主体有人、狗、猫、卡通；文本有很短、很长、别的语言）。
- [ ] 逐条看结果，别只看第一条：像不像、格式对不对、有没有多出的东西。
- [ ] 失败率高的选项，先改提示词，不行就删掉。
- [ ] 换模型或模型升级后，整套重跑一遍。

## 5. 上线
- 生成失败（超时、报错、被模型拒绝）自动退额度，并在页面上写明。
- 每次生成记下成本、耗时、失败原因：定价和选模型都靠它（→ `product-strategy`）。
- 模型服务挂了：重试、排队，或换备用模型；都不行就明确告诉用户稍后再试。
- 页面上披露用的模型（例 "Made with Seedance 2.0 Fast (ByteDance)"），只承诺模型做得到的。

## 视频生成
逐帧拆原片、按秒写动作和口型、原声当参考音频、场景选项和英文模板：见 `references/video.md`。
